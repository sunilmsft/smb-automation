# 04 Collaboration Context

## Team model
This repository reflects a partnership workflow between Tim and Sunil:
- Sunil: product, technical design, AI implementation leadership.
- Tim: partner alignment, opportunity shaping, and expected sales/ops contribution.

## Collaboration artifacts
Collaboration continuity is encoded in:
- context.md for current strategic framing.
- memory.md for session-by-session decisions, findings, and open questions.
- .github/copilot-instructions.md for operational conventions and repeatable editing guardrails.

## Decision cadence pattern
The collaboration pattern is:
1. Explore and evaluate opportunities.
2. Rank and filter with explicit criteria.
3. Preserve rationale and open questions.
4. Revisit with updated assumptions and market signals.

## Working style represented in the repository
- Conversational decision-making captured as durable records.
- Explicit tradeoff documentation (speed, trust, complexity, upside).
- Shared reference artifacts that can be used asynchronously.

## Why this context matters for preservation
Without this collaboration layer, the project can look like static files.
With preserved collaboration context, the repository remains a reusable operating playbook for future ventures.
